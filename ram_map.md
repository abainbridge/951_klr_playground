# KLR RAM map

GENERATED BY AN AI.

What each of the 128 RAM bytes is used for in the stock 1987 KLR firmware (`rom.bin`).

## How to read this

- **Evidence:** every reader and writer of each byte was recorded in an instrumented copy of the simulator (idle, fixed speeds, full throttle, sensor fault scenarios and random inputs), then the instructions at those addresses were read in `Annotated_Stock1987_951KLR.asm`.
- **Confidence:** High means the code leaves little room for another reading. Medium means the mechanism is clear but the name is my interpretation. Low means a best guess.
- **Example values** come from the simulator held at a steady speed for 4 seconds, with the knock noise reading at 60 and the knock integrator reading at 250 (no knock, no faults).
- **Code addresses** are ROM addresses as in the listing.

### Stack (`08h`-`17h`)

Eight 2-byte slots holding return address and flags. Seven were reached in the runs.

The eighth slot (`16h`-`17h`) has a second job. Each trigger resets the stack pointer to zero, so the `ret` at `02B0` pops from this slot. The firmware uses that to resume the housekeeping list at `0800` where the previous cylinder's pass was cut off: `17h` is set to 8 and `16h` holds the low byte of the address in the list.

| `1Dh` | r5 | Scratch; loop counter in the multiply. Also written through a pointer at `0CD2` during map interpolation. | High |
| `1Eh` | r6 | Scratch; the other multiply input. Loaded with the engine period `24h` at `014C`. | High |
| `1Fh` | r7 | Scratch and loop counter. | High |

## How the main groups fit together

- **Spark delay pipeline:** retard `73h` + `3Fh` -> delay `28h`/`29h` -> `20h`/`21h` -> `26h`/`25h` -> bank 0 `r2`. Each arrow is one trigger, so a retard decided for a cylinder takes effect two triggers later.
- **Knock:** integrator reading `46h` is compared with the cylinder's running average `7Ah` x factor `47h`. Knock adds 9 to `73h`; `49h`/`4Ah` let it decay; `4Bh` caps it.
- **Boost:** map target less the knock reduction `57h` gives `51h`, filtered into `53h`. Error against measured boost `52h` goes through the three controller terms `60h`, `61h`, `62h` into `63h`, is combined with feedforward `68h`, and ends as the valve duty in `41h`.
- **Faults:** counters `30h`, `34h`, `35h`, `36h` each count down on bad passes and store a code in `33h` at zero. `32h` blinks it out.

## The diagnostic routine at `0336` and `7Ch`-`7Fh`

The routine is called once per cylinder (`02A1`), and also from the low-speed start-up path (`01A3`). It reads the ADC (`033A`; the listing says the throttle sensor channel is selected at that point) and treats the reading as a command: the top three bits choose the action and the low nibble is data.

| Reading | Action |
|---|---|
| bit 5 clear | Shift the low nibble of the reading into `7Fh`; each byte's old low nibble moves to its high nibble and its old high nibble moves on to the next byte down, ending at `7Ch`. If bits 6 and 7 are also clear (reading below `20h`), then clear `7Dh` and the high nibble of `7Eh`. |
| `20h`-`3Fh` | Write out eight bytes (below), with the external address offset by 0-3 depending on the cylinder counter `2Ch`. |
| `60h`-`7Fh` | Write out the raw contents of `7Fh`-`7Ch`, followed by the four constants `41h`, `68h`, `60h`, `53h`. |
| `A0h`-`BFh` | If `7Dh` is zero: read one ROM byte and store it in `7Ch`. The ROM address is the low nibble of `7Eh` (page) and `7Fh` (offset). It works by planting the address `xFEh` on the stack so that a `ret` lands on the `movp a,@a` stub at the end of that page. |
| `E0h`-`FFh` | Write out eight bytes (below). |

The eight bytes written out are the contents of the four RAM addresses held in `7Fh`, `7Eh`, `7Dh`, `7Ch`, then the contents of `41h` (valve duty), `68h` (feedforward), `60h` (boost error) and `53h` (filtered target boost). Those last four addresses come from a small table in ROM at `03FA`-`03FD`, which the listing shows as instructions.

So `7Ch`-`7Fh` is a small command buffer for a memory monitor: load it with RAM addresses to watch, or with a ROM address to read.

**Where the bytes go:** they are written with `movx @r1,a` to external addresses `80h`-`87h`. That instruction puts the byte on the 8048's bus pins and pulses the WR pin (pin 10). On this board pin 10 is not connected to anything (checked on the 1987 UK unit), so nothing on the board receives these writes. The bytes only appear briefly on the bus pins. My guess is that this is a development or factory test aid that needed extra equipment attached to the chip.

**In normal running** the routine still executes every cylinder, so ordinary throttle readings are treated as commands: the buffer fills with throttle nibbles and bytes are written to the bus with no effect. The example values in the table above show this (`33 33 33 33` at full throttle is the low nibble of the throttle reading `C3h`).

**Simulator note:** the addresses in the buffer are used unmasked. With throttle nibbles in it, the routine reads RAM addresses such as `88h`, which is past the end of the simulator's 128-byte `ram` array.

## Things I could not pin down

- **ADC channels 2 and 6:** the firmware converts both but uses neither. Channel 6 is stored in `2Dh` and never read. Channel 2 is read once every 4 cylinders and discarded at `0482`; that code loads the address `6Fh` and then has a `nop` where a store would be. What either input is connected to has not been traced.
- **`4Ch`, `4Dh`, `4Eh`:** clearly part of the logic at `0DA5`-`0DD6` that raises the boost reduction `57h`, but I have not worked through that code in full.
- **`67h`:** behaves like a slow adaptive correction, but the name is a guess.
- **`31h` and `34h`:** tied to the knock self-test and fault code 23; the exact sequence is not worked out.
